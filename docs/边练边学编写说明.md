# “边练边学”题库编写说明（data/learn/LNN.json）

学生不先看笔记，直接按讲义顺序做题来学。每题先显示考点和「怎么用」，答完显示逐步解题过程。目标：读完解题过程就等于学会了这个知识点。

## 考试背景

期末 80 道单选（社会 L1–4 共 20 题，发展 L5–8 共 30 题，人格 L9–12 共 30 题），英文，答错不扣分。所以这里**全部是四选一单选题**，不出判断题。教授练习题的结构化版本在 `data/review-social-dev.json` 和 `data/review-personality.json`，代表真题风格。

## 文件格式

```json
{
  "lectureId": 3,
  "points": [
    {
      "id": "L3-P01",
      "title": "考点中文名",
      "titleEn": "English name",
      "conceptIds": ["L3-C01", "L3-C02"],
      "kp": "知识点本身：一两句完整中文说清它是什么，关键英文术语保留。≤130 字",
      "howTo": "解题规则：看到题干里的什么线索就选什么，要具体到能照着操作。≤120 字",
      "items": [
        {
          "stemEn": "English question",
          "optionsEn": ["A", "B", "C", "D"],
          "answer": 2,
          "stem": "中文题干",
          "options": ["中文A", "中文B", "中文C", "中文D"],
          "how": ["第一步：指出题干线索，引用原词（用「」）。", "第二步：套用规则，得出答案，所以选 C。", "第三步（可选）：最易错选项为什么不对。"]
        }
      ],
      "recap": "做完这个考点后应该记住的一句话，可用「A → B」口诀。≤80 字"
    }
  ]
}
```

考点 id 用该讲的不补零编号：`L3-P01`、`L10-P01`。concept id 以 `data/LNN.json` 里实际写法为准。

## 考点怎么划分

1. 内容依据 `data/LNN.json`：`concepts`（知识点）和 `sourceBlocks`（整理笔记）。**按笔记出现的顺序**排列考点。
2. 每讲 **10–16 个考点**。一个考点是一个能用一条规则解题的单元：太大就拆，太小就合并。`conceptIds` 列出它覆盖的知识点。
3. **本讲每个 concept 都要被至少一个考点覆盖**（`node build.js --check` 会提醒没覆盖的）。只有老师明确说不考的思考题、课堂闲谈可以不覆盖，并在汇报里说明。
4. 容易混的比较、经典实验的数字和结论、笔记标注的易错点要有专门的考点或题。教授练习题考到的点必须覆盖。

## 题目怎么出

- 每个考点 **3–5 题**，由易到难：先直接辨认，再情境应用，最后区分干扰概念或考易错点。
- `stemEn` / `optionsEn` 是英文，风格同教授练习题，多用具体情境；干扰项用课程里真实存在的相近概念，不要凑数；选项长度相近，正确项不要总是最长的。`stem` / `options` 是忠实的中文翻译，术语写「中文（English）」，不加提示。
- 选项不打乱，四个答案位置大致均匀，所以 `how` 里可以直接写字母。
- 不要照抄教授练习题，也不要照抄 `data/LNN.json` 已有的题（改编不超过四分之一，`how` 必须新写）。
- 数字、人名、研究结论**只能来自笔记**，不能编。

## `how` 怎么写（最重要）

- 2–4 步，每步一句话，≤85 字。
- 第一步**指出题干线索**，引用题干原词；第二步**套规则得答案**，写明「所以选 X」；有易错选项时再用一步说它为什么不对。
- 直接了当：不要「我们可以看到」「值得注意的是」；不重复题干；不讲无关内容。
- 完整句子，不用 `=`、`→` 代替动词；英文只留术语。

## 校验

在 `E:\PSYC1004\复习软件` 运行 `node build.js --check`，改到没有报错，并处理「提醒」里没覆盖的知识点。字符串里不要出现未转义的英文双引号，引用用「」。其他人在同时写别的讲；如果报错只来自别的讲的文件，不要改它们，在汇报里说明即可。
